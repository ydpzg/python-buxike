# 内容写法

## 一章的结构

建议一章 12 个场景：

1. 封面。
2. 概念一。
3. 概念二。
4. 概念三。
5. 概念四。
6. 扩展：真实例子。
7. 扩展：常见错误。
8. 扩展：边界情况。
9. 扩展：调试或验证。
10. 扩展：设计取舍。
11. 练习。
12. 回顾。

每章至少 45 个 beat。普通 beat 约 5–10 秒，一章自然落在 3.5–5 分钟。

## Beat

`(旁白, 板书)` 中：

- 旁白是学生听到的完整句子。
- 板书是学生需要留痕的概念、关系、代码或步骤。

不要把完整旁白原样复制到板书。板书应压缩为关键词、关系和例子。

不要写：

```python
("|if x > 0:|    print('正数')", "判断正数")
```

应写：

```python
("条件成立时，执行缩进里的打印语句。", "|if x > 0:|    print('正数')")
```

## 练习

练习页使用 `layout="practice"`，包含 5 个 beat：

1. 题目。
2. 流程。
3. 左侧实现。
4. 右侧验证。
5. 验收说明。

并设置：

```python
scene["checks"] = ["正常输入", "边界输入", "失败情况"]
scene["practice_tags"] = ("write", "query")
```

## 回顾

回顾不是目录复述。每个卡片要回答一个具体问题：

- 这章学会了什么概念？
- 怎样判断程序正确？
- 练习做了什么？
- 下一步如何扩展？
- 下一章学什么？

## 文案检查

优先用短句。技术词首次出现时给出中文解释。不要把英文标点直接混进中文句子，也不要让 TTS 读代码符号。
