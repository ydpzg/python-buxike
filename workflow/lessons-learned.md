# 制作经验与问题记录

这份文档记录实际做 15 章视频时暴露的问题，以及下一套视频应该提前避免的地方。

## 1. 首屏必须有章节标题和老师

只放黑板或只放章节号都不够。第一帧应同时出现：

- 章节号。
- 章节名称。
- 老师人物。

标题画面持续到开场旁白结束，再切到正文。开场字幕必须同时出现，不能因为封面保持而把字幕丢掉。

## 2. 不要直接念黑板代码

黑板上需要代码，旁白需要解释代码。示例：

- 板书：`|data = response.read()|text = data.decode('utf-8')`
- 旁白：网络先返回字节，按正确编码解码后，才能当作文本处理。

如果数据把代码放在旁白字段，TTS 和 SRT 就会出现 `|客户端|`、`|GET ...|` 这样的标记。应在加载内容时统一规范化 beat，并给修改后的旁白设置新的音频缓存名。

## 3. 板书要保留关键内容

正文不能只有“变量”“函数”这样的短标签。一个知识页至少应包含：

- 概念名称。
- 作用或规则。
- 一个最小例子。
- 容易出错的地方。

片尾回顾要写本章具体概念，不能复用“把概念变成程序”“本章关键概念”这类通用标题。

## 4. 练习必须单独成页

练习页按顺序展示：

1. 题目。
2. 解决流程。
3. 左右两个代码面板。
4. 验收标准。

练习标题必须出现在板书和片尾回顾中。先展示题目和约束，再展示实现，避免学生一打开页面就看到答案。

## 5. terminal 代码必须保留缩进

数据中需要明确保留行首空格，渲染代码面板时不要经过 `strip()`。超长行按实际可见宽度逐行缩小字体。

检查：

```bash
rg -n '^\|' outputs/*.srt
```

不应有匹配。

## 6. 文案细节

- CPU 主频写 `3.0 GHz` 或“三点零吉赫兹”，不要写“三点零吉”。
- 中文问号直接跟在句子后面。
- 不要为了换行单独打一个 `?`。
- 中英文和数字之间留空格。
- 删除无意义的大号 `01` 水印。

## 7. 时长异常先查数据

3–15 章曾只有 1 分多钟，原因是扩展场景没有进入最终 `SCENES`，音频又复用了旧缓存。排查顺序：

1. 检查 timeline 的 scene 和 beat 数量。
2. 检查 `EXTENDED_SCENES` 是否被合并进 `SCENES`。
3. 检查 `--reuse-audio` 是否指向旧文案缓存。
4. 检查每个场景的旁白长度。
5. 再检查 ffmpeg 合成时长。

完整章节建议 3–5 分钟。少于 3 分钟时，先补内容和练习，不要靠拉长静音凑时长。

## 8. 审查方式

不要只跑命令后直接交付。至少检查：

- 首屏静帧。
- 开场旁白结束时的字幕。
- 每个练习页。
- 每个片尾页。
- 代码缩进和行宽。
- SRT 是否含代码管道符。
- 全部章节时长。

大型审查应拆成子任务，每个子任务只检查 2–3 章，并返回具体帧和问题。否则一次性塞入大量截图和转录容易超过上下文限制。

## 9. 发布前

- 每章 MP4、SRT、timeline 同名。
- YouTube 标题和简介统一放在 metadata 目录。
- 播放列表使用课程总标题。
- 不在公开仓库提交原始音频缓存和整帧图片。
- 大视频单独存对象存储或 Release，不直接塞进 Git 历史。
